<Chalk>two vendors, one instruction: say less</Chalk>

<p class="lede">
You keep two prompting guides open because you run two model families, and you assume they
disagree. Read them side by side and the surprise is how much they don't. OpenAI's
<a href="https://developers.openai.com/api/docs/guides/latest-model">latest-model guide for GPT-5.6</a>
and Anthropic's
<a href="https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices">prompting best practices</a>
now open on the same instruction, phrased two ways: lean out the prompt. The habits you built to
wrestle older, weaker models are the exact habits both vendors are now telling you to unlearn.
</p>

## <span class="sec-no">01</span>Where they converge

OpenAI's core advice is blunt: remove repetition, simplify tool descriptions, and state each
instruction exactly once. It calls out approval-gating specifically. Strip the scattered "ask
first" and "wait for approval" phrases, and instead define once what level of action each request
authorizes. Say explicitly which actions the model may take on its own and which need a human,
so it stops pausing where it shouldn't while still blocking anything external, destructive, or
costly.

Claude's guide lands in the same place from the other side. It tells you to soften the aggressive
anti-undertriggering language, the "CRITICAL, you MUST use this tool" phrasing that current
models over-respond to, down to plain "use this tool when." And it warns that these models
overengineer by default, reaching for extra files and unrequested abstractions, so a minimalism
instruction earns its place.

Both diagnoses share a root cause. The emphasis and repetition you learned were compensating for
models that under-followed instructions. Current models follow them literally and weight an
over-emphasized rule too heavily, so the compensation now backfires. Lean prompts aren't a style
preference here. They are the correction for a capability that improved underneath your habits.

## <span class="sec-no">02</span>Where they genuinely diverge

Convergence on the prompt doesn't mean convergence on the machine. Three splits are real, not
cosmetic.

Reasoning control. OpenAI exposes a numeric ladder, reasoning.effort from none through max, plus
a reasoning.mode "pro" switch that spends more model work on one request before returning a single
answer. Claude runs adaptive thinking calibrated by an effort parameter and query complexity,
with the model deciding depth per turn rather than you selecting a rung.

Tool orchestration. OpenAI's Programmatic Tool Calling lets the model write code that calls tools
server-side, process several results, and hand back one small structured payload. It's meant for
bounded filter, aggregate, and validate work, not decision-dependent sequences. Anthropic's
analogous path keeps orchestration in the client loop or its code-execution tool (labeled analyst
inference, not a claim on either page).

Reasoning reuse. OpenAI carries encrypted reasoning across turns with previous_response_id plus
reasoning.context, so prior thinking can persist when goals stay stable. Claude re-sends thinking
blocks in the conversation history instead (also analyst inference). Same goal, opposite plumbing,
and the integration code is not portable between them.

## <span class="sec-no">03</span>Read the eval numbers at the right altitude

OpenAI reports internal evals where leaner prompts scored roughly 10-15% higher while cutting
tokens 41-66% and cost 33-67%. Those numbers are the strongest argument in the guide, and they
are also the softest. They're self-reported, with no methodology, task mix, or baseline stated,
so you cannot tell whether they hold on your workload or on a benchmark shaped to flatter the
advice.

What makes the direction trustworthy isn't the magnitude. It's that the other vendor moved the
same way independently. Two houses telling you to cut repetition, from different eval harnesses
and different model architectures, is stronger evidence than either vendor's percentage. So take
the direction as settled and the numbers as an invitation. Run the before-and-after on your own
prompts and measure your own delta, because that is the only number that describes your system.

<Exercise>
1. Take one production prompt and grep it for "ask first", "wait for approval", "CRITICAL", and
   "you MUST". Replace every hit with a single autonomy statement up top: what the model may do
   alone, what needs a human. Count the tokens you removed.
2. Run the original and the leaned version against ten representative tasks. Compare quality and
   token spend yourself rather than trusting either vendor's percentage. That delta is your real
   number (and <a href="/guides/thinking-on-a-budget/">Thinking on a budget</a> is the guide to
   shrinking it further).
3. If you run both families, list the three divergences that don't port (reasoning control, tool
   orchestration, reasoning reuse) and note which of your integration code assumes one vendor's
   plumbing.
</Exercise>
