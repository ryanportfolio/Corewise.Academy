<p class="lede">Build an AI setup around a job you already know how to judge. For client onboarding questions, give the agent your approved procedure, require supporting passages, and check what happens when a fact is missing. Keep the working files and corrections so the next session can use them.</p>

Austin Marchese's [Stop Prompting Claude. Start Harness Engineering.](https://www.youtube.com/watch?v=bIYWxYm5cOY) describes extending an existing agent with your own knowledge, procedures, and interface. His internal-knowledge example provides a concrete starting task. Our [Harness Firmware](https://harnessfirmware.com) provides repository workflows and project memory for maintaining that setup; it is our implementation, separate from his demo.

## <span class="sec-no">01</span>Extend the agent you have

A **harness** is the software around a model that supplies tools, manages context, and runs actions. Anthropic's [Claude Code architecture](https://code.claude.com/docs/en/how-claude-code-works) describes a loop of gathering context, acting, and checking results. Claude Code already supplies that loop.

Marchese calls the instructions, files, and procedures specific to your work a **domain harness**. You can add those to an existing agent. Rebuilding file access, tool execution, and session handling would give you more software to maintain before the work-specific task runs.

## <span class="sec-no">02</span>Choose one task you can judge

Pick a recurring task where you have the inputs and can recognize a wrong result. Marchese's [domain-selection advice](https://www.youtube.com/watch?v=bIYWxYm5cOY&t=262s) starts with work you already understand. A personal setup can use your exact procedure and preferences because you can specify them.

He distinguishes people who build models, use existing products, and customize them. Customize a tool when it repeatedly fails to do something you need. A standard tool may already handle the task well enough.

Write down:

- The question or request that starts the task.
- The files or tools needed to complete it.
- The required output and how you will check it.
- The repeated correction you want to remove.

For onboarding questions, the output is an answer supported by the current onboarding procedure. The correction might be removing steps the agent invented. [Choose AI changes worth your time](/guides/choose-ai-changes-worth-your-time/) covers comparing setup, review, and maintenance effort before keeping a custom tool.

## <span class="sec-no">03</span>Give each part a purpose

Marchese [lists eight parts](https://www.youtube.com/watch?v=bIYWxYm5cOY&t=448s). Use them as a checklist when a task needs them:

| Part | Job in a document-answering setup |
| --- | --- |
| Rules | Require approved sources, supporting passages, and an explicit missing-answer response |
| Skills | Package separate procedures for answering questions and refreshing documents |
| Connections | Fetch approved documents from their source when local copies need updating |
| Context | Supply the actual procedures and reference documents |
| Hooks | Run a specific check when a named event occurs |
| Subagents | Handle a separate task with its own inputs and completion check |
| Interface | Let you ask, inspect sources, refresh files, and report a defect |
| Feedback | Keep the failed question and correction so you can repair and rerun it |

Claude Code documents [skills](https://code.claude.com/docs/en/skills), external connections through [MCP, the Model Context Protocol](https://code.claude.com/docs/en/mcp), and event scripts through [hooks](https://code.claude.com/docs/en/hooks). A folder of approved documents and an answer procedure may be enough for the first version. Add a connection when manual updates become a problem; give any hook or extra worker a specific job before adding it.

[Set up an AI that knows your business](/guides/set-up-an-ai-that-knows-your-business/) covers organizing context and linked knowledge. [Write smaller Claude skills that work](/guides/write-smaller-claude-skills-that-work/) covers packaging a procedure without loading every instruction into every task.

## <span class="sec-no">04</span>Check answers against the files

Marchese's [knowledge example](https://www.youtube.com/watch?v=bIYWxYm5cOY&t=554s) separates `KB answer`, which answers from local context, from `KB sync`, which brings in source material. Keep that separation so a question does not silently change the documents used to answer it.

Require a path and supporting passage for each answer. If the files disagree, show the conflict; if they lack the fact, say what is missing. Anthropic's [instruction-file documentation](https://code.claude.com/docs/en/memory) distinguishes written guidance from enforced controls. A source-only instruction can still be disobeyed, so inspect the evidence.

Use a small set of questions with known outcomes:

| Case | Passing behavior |
| --- | --- |
| Answer appears in an approved file | Answer matches the cited passage |
| Files lack the answer | Agent reports the missing fact without inventing it |
| Two files disagree | Agent identifies both passages and leaves the conflict visible |
| An approved source changes | After refresh, the answer uses the new version and cites it |

Keep the source path and retrieval date with refreshed documents. [Keep a growing knowledge base accurate](/guides/keep-a-growing-knowledge-base-accurate/) covers stale files, broken routes, and repairs after a failed search. [Score your agent on known good answers](/guides/score-your-agent-on-known-good-answers/) covers maintaining repeatable checks.

Record feedback as the question, answer, cited files, defect, and accepted correction. A later run must use the repaired data or procedure and pass the same check. Saving feedback alone does not train the model's weights.

## <span class="sec-no">06</span>Make the interface do the work

Keep the existing chat or terminal while the answer procedure is still changing. Marchese [prefers a local web interface](https://www.youtube.com/watch?v=bIYWxYm5cOY&t=805s) for quick edits and visible controls. Build one when it makes your task easier to run or check.

His demo has Send, Sync, and feedback controls. Verify what each control does:

- **Send** calls the answer procedure and displays the answer with its sources.
- **Sync** runs the approved refresh procedure and reports which files changed or failed.
- **Feedback** saves the failed case and correction for later review.

A page that displays a plausible answer without calling the agent has not passed. Inspect the run record and test the same question through the interface and directly in the agent. Claude Code's [programmatic interface](https://code.claude.com/docs/en/headless) supports noninteractive calls and structured output; the local app needs a working process that invokes it.

Check authentication and usage before relying on Marchese's subscription-cost claim. Claude Code supports [subscription and API authentication](https://code.claude.com/docs/en/authentication), and some programmatic modes use different credentials. Hosting the page locally does not determine how model calls are billed.

Before giving the tool to a team, define who can read each source, refresh it, and accept a correction. [Build a knowledge base your team can ask](/guides/build-a-knowledge-base-your-team-can-ask/) covers the larger system. Marchese leaves team deployment outside this demo.

His closing ["Karpathy curve" discussion](https://www.youtube.com/watch?v=bIYWxYm5cOY&t=900s) puts future value in choosing data, breaking down tasks, and adapting work around models. Treat that as his interpretation. For this setup, you can check the narrower claim: whether your files and procedures reduce unsupported answers and repeated corrections.

Use this original prompt to plan your first version:

```text
I want an AI setup for [one recurring task] using [approved source folder]. Ask for any missing requirement that would change the plan. Inspect the existing agent's tools and instructions first.

Define the required output and evidence for correctness. Propose the smallest addition to the existing agent that would meet those requirements. For document questions, separate answering from source refresh, require file paths and supporting passages, report missing facts, and expose conflicting sources.

List checks for a supported answer, an absent answer, conflicting files, and an approved source update. Explain which parts I must inspect myself. Record failed cases for review; preserve permission limits.

Keep the first version in the existing chat or terminal. Add a web interface only if it helps the task, and specify how each control will invoke the real procedure and report failures. State the execution and billing method. Return the plan for my review before building or connecting services.
```
