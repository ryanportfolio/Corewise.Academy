<Chalk>the cheapest token is the one never written</Chalk>

<p class="lede">
Watch an agent work with the transcript open and you will see money being narrated away. It
restates the request it was just given. It hedges ("likely", "seems to", "I'm considering")
3 times in a paragraph. It closes by summarizing a diff that is already on screen. Every one
of those words is billed at the output rate, the most expensive class of token there is, and the
model's private reasoning rides the same meter. Then the bill compounds: everything written into
a session is re-read as input on every turn that follows. Verbosity taxes you twice. This guide
is about paying less: not by thinking less, but by saying less while knowing exactly as much.
</p>

## <span class="sec-no">01</span>Two meters run in every session

The first meter is deliberation depth: how long the model reasons before it answers. That one is
controlled at the harness (effort levels, thinking budgets, model routing), and <a href="/guides/rent-the-model-own-the-method/">Rent the model, own the method</a>
covered how to set it per task. The second meter is prose verbosity: how many words the
model spends performing its work back at you. It is controlled by instruction, it is almost
always set too high by default, and it is the one this guide turns down.

The distinction matters because the two failure modes are opposites. Cut deliberation too far
and the model gets the answer wrong. Cut prose too far and the model gets the answer right but
the reader loses it: order becomes ambiguous, a caveat vanishes, a warning gets skimmed. So the
levers must move independently: a hard debugging task might want maximum deliberation and
minimum narration, while an irreversible migration wants the model's full prose attention
regardless of what thinking it took to get there. Collapsing the two meters into one vague
instruction ("be brief") is how you end up cutting the wrong one.

## <span class="sec-no">02</span>The compression contract

What works in practice is not an adjective but a contract: a written mode the agent runs under,
with an intensity ladder, a set of inviolables, and an explicit statement of what wins when
brevity and accuracy collide. The ladder gives you graduated stops rather than one cliff:

| Stop | What changes | Prose spend, by design target |
| --- | --- | --- |
| Light | Filler and hedging die; full sentences survive | Roughly 30% off |
| Full | Articles drop, fragments allowed, short synonyms | Roughly 50% off |
| Ultra | Abbreviations, stripped conjunctions, arrows for causality | About 75% off |

At the far end, a sentence of causal narration becomes an arrow chain: inline
object prop → new reference → re-render. Six tokens, and nothing a practitioner needed is lost.

The inviolables are what make the far end safe:

- Code, symbols, function names, API names, and error strings are never abbreviated: they are
  load-bearing, and a paraphrased error message is a lie.
- Facts, caveats, and qualifiers are never dropped to save tokens; the contract compresses
  wording, not meaning.
- When terseness would risk a misread, spend the words: accuracy beats brevity.
- Before writing any summary, ask whether the tool output already shows it. A self-evident diff
  needs no closing narration.

The cheapest token is the one never written.

## <span class="sec-no">03</span>Carve-outs, and the tell that you cut too deep

A compression mode without escape hatches is a liability, so the contract names the places it
must drop back to plain prose automatically. Security warnings: a skimmed fragment
under-communicates risk. Confirmations before irreversible actions: the user must fully
understand what is about to happen, at whatever token cost. Multi-step sequences where dropped
connectives make order ambiguous: "migrate table drop column backup first" reads two ways, and
one of them loses data. And the moment a user asks for clarification, that topic has earned
plain language. The carve-outs are not exceptions to the economics; they are the economics:
each one marks a spot where the failure cost of compression exceeds its savings.

Which is also how you audit the whole scheme. Token savings are real only at the conversation
level. A terse reply that forces a clarification round-trip costs the original message plus the
question plus the re-explanation, with the whole exchange re-read as context on every subsequent
turn, more than plain wording would have cost once. So the tell that you have over-compressed
is not in the message you sent; it is in the reply you get.

> “The tell that you have over-compressed is not in the message you sent; it is in the reply you get.”

A repeated question. A "what do you
mean by". A request to re-explain. Treat those as meter readings, and route the topics that
generate them back up the ladder. The same accounting, incidentally, applies to what enters the
context as much as what leaves it (filtered tool output, thin always-loaded instructions with
detail split into files loaded on demand), but the discipline is one discipline: every token,
in or out, either carries meaning or carries cost.

> “Every token, in or out, either carries meaning or carries cost.”

Keeping that always-loaded layer thin is its
own craft in <a href="/guides/firmware-not-folklore/">Firmware, not folklore</a>.

<Exercise>
1. Open a recent agent session transcript and highlight every sentence that restates the
   request, narrates a change already visible in a diff, or hedges without adding information.
   Estimate the tokens; even 20 minutes of transcript usually surprises. That number is your
   verbosity meter, and it is probably not small.
2. Write a compression contract for your own agent: an intensity ladder with at least two
   stops, the inviolables (code, error strings, facts, caveats), and the carve-outs that force
   plain prose. Install it as a skill or standing instruction, not a per-session request; the
   packaging move is <a href="/guides/expertise-you-can-install/">Expertise you can install</a>.
3. Run it for 7 days. Compare spend against the prior week, but audit the transcripts for
   clarification round-trips: every "can you re-explain" is a topic to route back to plain
   language. Tune the ladder, keep the contract.
</Exercise>
