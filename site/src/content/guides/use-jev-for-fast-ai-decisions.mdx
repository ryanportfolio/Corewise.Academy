<p class="lede">
An incoming support message needs a destination, a priority, and someone to handle it. Jev evaluates information against questions and possible answers you define, so it can help sort that queue. Define those decisions, use their probabilities to route work, and check the results before automating.
</p>

## <span class="sec-no">01</span>Choose the answer type

TypeSafe calls Jev a System One model: a model built for fast, focused judgments that software can use directly. You supply the **state**, meaning the information to evaluate, and a **schema**, meaning the structure of the questions and answers. Jev returns values for code to use. A separate generative model writes replies or summaries. [TypeSafe introduction](https://docs.typesafe.ai/introduction).

| Type | Use it for | Read the result as |
| --- | --- | --- |
| **Choice** | Which team should handle this message? | One of your named options, with probabilities and confidence |
| **Score** | How much does this issue disrupt the customer's work? | A position on ordered levels you describe, with probabilities and confidence |
| **Noul** | Does this message request a refund? | The predicted probability of yes, from 0 to 1 |

A [Choice](https://docs.typesafe.ai/primitives/choice) needs options that separate the possible answers. Add `other` when the list might miss a case. A [Score](https://docs.typesafe.ai/primitives/score) needs descriptions for each level. Three levels are numbered 0, 1, and 2; the returned score can fall between them.

With [Noul](https://docs.typesafe.ai/primitives/noul), 0.5 means yes and no have equal probability. It does not mean medium urgency or medium lead quality. Define a scale with Score when you want to measure degree.

## <span class="sec-no">02</span>Make the questions precise

Give each question one judgment to make. Automation creator Nate Herk's [I Tested Jev on 12 Real Use Cases. My Honest Thoughts.](https://www.youtube.com/watch?v=ymgH8jS6Wb8) demonstrates this with separate questions for billing messages, sponsorship inquiries, urgency, and sponsor fit. Each answer becomes a usable column; a broad request to analyze an inbox leaves the desired output undefined.

Write the full question in `instructions`; the question ID is only for your code. Questions in one request run independently against the same state. Combine the answers afterward. If one answer is needed to fetch new information, make a second request with that information. [Question design](https://docs.typesafe.ai/primitives).

This original request follows the [direct API's documented format](https://docs.typesafe.ai/introduction/quickstart); it has not been tested against the live service. Send it to `POST https://api.typesafe.ai/v1/systemone` with `Authorization: Bearer YOUR_API_KEY` and `Content-Type: application/json` headers, or recreate the questions in TypeSafe's playground.

```json
{
  "model": "jev-latest",
  "state": "The dashboard stopped loading this morning. Our team cannot process orders, and we have no workaround.",
  "questions": {
    "department": {
      "type": "choice",
      "instructions": "Which team should handle the main issue in this message?",
      "criteria": {
        "billing": "Charges, invoices, or payment collection",
        "technical": "Broken features, outages, or integration failures",
        "other": "A request outside billing and technical support"
      }
    },
    "impact": {
      "type": "score",
      "instructions": "How much does the reported issue disrupt work?",
      "criteria": [
        "Work continues normally",
        "Work is disrupted but a workaround exists",
        "Work is blocked and no workaround is available"
      ]
    },
    "refund_requested": {
      "type": "noul",
      "instructions": "Does the message explicitly request money back?"
    }
  }
}
```

As of September 19, Vercel also offers Jev through [AI Gateway](https://vercel.com/ai-gateway/models/jev), using `experimental_evaluate` and model ID `typesafe-ai/jev`. Its example uses `boolean` for a yes-or-no question. Follow the documentation for the interface you choose; the request above is for TypeSafe's direct API.

## <span class="sec-no">03</span>Keep decisions and actions apart

Separate how well a request fits your service from how certain the model is about that judgment. In [Jev is HERE. How to use it](https://www.youtube.com/watch?v=4mTLpuQpB80), podcast host Greg Isenberg and guest Ryan Vogel explore business routing through a design agency's contact-form leads. An uncertain lead may need clarification. Quietly discarding it could lose a customer.

Choice and Score return `confidence`, derived from how their probabilities are distributed. It is a separate field from the winning option's probability. Noul has no separate confidence field. [Confidence documentation](https://docs.typesafe.ai/confidence).

Our routing recommendation:

| Result | Next step |
| --- | --- |
| Clear fit for a tested category | Route to the corresponding queue |
| Ambiguous fit or missing information | Keep the item visible for review or clarification |
| A reply or detailed explanation is needed | Pass the source material to a person or generative model |

Choose thresholds from errors on your own examples. Keep permissions and execution in code: selecting a refund category must not itself issue a refund. [Assume your agent uses every tool it has](/guides/assume-your-agent-uses-every-tool-it-has/) covers that boundary.

Herk applies the same division to YouTube comments: classify the pile, then send selected comments to a model that can write responses. [Build an agent that finds your customers](/guides/build-an-agent-that-finds-your-customers/) uses the same rule: call a model at the steps that need judgment.

## <span class="sec-no">05</span>Supply enough context to judge

Choose questions the supplied evidence can answer. Developer creator Theo's [Jev is incredible](https://www.youtube.com/watch?v=F3YXg7AaKWE) adds a useful limit: a quick classifier may lack the context needed to judge a whole implementation or decide which conversation history an agent can afford to lose.

**Keep evaluation narrow.** Checking whether a reply contains a required disclosure is a focused judgment. Choosing the best of several code implementations may require reading dependencies and running tests. Theo challenges that use at [12:40](https://www.youtube.com/watch?v=F3YXg7AaKWE&t=760s). Our recommendation is to validate each judging task separately, using [Score your agent on known good answers](/guides/score-your-agent-on-known-good-answers/). TypeSafe's own [question guidance](https://docs.typesafe.ai/primitives) favors focused judgments and splitting complex ones into smaller questions.

**Carry prior actions forward.** Theo observes repeated left-right turns in a game demo and attributes them to decisions made without the previous action. For a repeated decision, our recommendation is to include the current goal, recent action, and its result in the next state. Jev currently takes text or JSON state, not screenshots; the surrounding program must supply those facts. [State documentation](https://docs.typesafe.ai/concepts/state).

**Treat history deletion as a separate experiment.** Theo's [compaction critique](https://www.youtube.com/watch?v=F3YXg7AaKWE&t=1383s) concerns removing messages without enough evidence about what later work needs. Anthropic's [compaction](https://platform.claude.com/docs/en/build-with-claude/compaction) instead summarizes older context for continuing the task. A keep-or-drop classifier alone does not produce that summary. Keep the agent's supported context management unless your replacement passes tests of whether work resumes correctly.

History edits can also change the bill. Anthropic's [prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) reuses matching prefixes: changing an early message prevents reuse of cached prefixes that include it. Measure cache misses and recovery work alongside tokens removed. [Stop hitting your token limit](/guides/stop-hitting-your-token-limit/) covers the broader budget choices.

## <span class="sec-no">06</span>Keep probabilities for later use

Store the probabilities with the original record, question definitions, and model version. Theo's [chat-history analysis](https://www.youtube.com/watch?v=F3YXg7AaKWE&t=1609s) classifies past coding conversations, then changes category thresholds in a dashboard. With the same questions and saved results, changing a threshold needs no new model call.

The threshold changes what gets counted. Report it beside any category total, and inspect examples that cross the boundary. A stricter threshold can shrink a category without changing the underlying conversations.

Broad judgments still need checking. Theo reports that attempts to identify conversations worth making into videos kept selecting roughly half his threads despite prompt revisions. That limits how much to infer from the earlier clip-scoring demos: a passage can be self-contained without being worth publishing.

## <span class="sec-no">07</span>Check speed and accuracy

Herk reports that grouping more work into requests and running requests in parallel cut one email run from about 70 seconds to 6 seconds. That change is part of the application. Compare models with the same inputs, questions, parallel request count, and retry settings before attributing the whole difference to Jev.

TypeSafe's launch post lists $0.042 per million input tokens and free output. The service still charges for input. Its largest speed and cost ratios come from its own workflow evaluations, and the company says those gains are toward the high end. [Launch evidence and caveats](https://typesafe.ai/blog/introducing-system-one-models-and-jev).

The same post explains that its zero-hallucination figure means the output always matches the defined structure. **A valid category can still be the wrong category.** Berman's broader reliability language should be read with that limit. Theo also distinguishes a fixed output shape from fixed content: the format guarantee does not promise identical judgments on repeated calls.

The demonstrations also expose limits. Vogel says his Bitcoin experiment performs poorly; Herk calls his trading demo unvetted paper trading. Berman describes a chess win caused by the opponent running out of time despite stronger play. These examples support testing speed under a deadline, not assuming that quick decisions are good decisions.

Use the method in [Score your agent on known good answers](/guides/score-your-agent-on-known-good-answers/). Track wrong routes, missed urgent items, and review volume separately. A system that sends everything to review may avoid automatic mistakes while saving no work. Include review and fallback costs in the comparison.

This original exercise turns the four videos into a testable workflow:

<Exercise>
1. Pick one queue, such as support messages. Collect 100 representative examples with human-approved categories, including ambiguous and out-of-scope cases. Reserve part of the set for a final check after tuning.
2. Define one Choice, one Score, and one Noul question. Write each category and score level plainly. Decide where uncertain answers will go.
3. Run Jev and your current method on the same inputs under matched settings. Record wrong routes, missed urgent cases, review volume, total cost, and elapsed time.
4. Save probabilities with the inputs, questions, and model version. Compare thresholds on the tuning examples without calling the model again; changed questions require a new run. Evaluate the reserved examples once the rules are fixed. Inspect confident mistakes as well as uncertain answers.
5. Process new items alongside the existing workflow without changing their routes. Enable automatic routing only for categories whose measured errors meet your team's agreed limits.
</Exercise>

Repeat the comparison after changing criteria or models. [Recheck your model choices each release](/guides/recheck-your-model-choices-each-release/) makes that maintenance routine.
