# Phrasing standard

These pairs establish the editorial standard. They are examples, not banned phrases or instructions to make every sentence look alike. Keep accurate technical terms, qualifications, and the writer's voice.

| Rejected wording | Direct version | Reason |
| --- | --- | --- |
| Questions can expose omissions | Ask the agent to question you about requirements you have not specified | The original names a general benefit without saying who should ask or what is missing. In a paragraph already recommending an interview, cut it instead of repeating the advice. |
| Give a business concept the same name in the conversation, requirements, interface, and code | If the people handling orders call an order "accepted," use that name in the app and code | The example names the thing and the action without making the reader translate "business concept." |
| Choose an initial task with a result you can inspect and mistakes you can correct | Build a local dashboard from sample orders before connecting it to customer data | The original leaves the reader to decide what qualifies. Use the task and limits already supplied by the context. If they are absent, ask what the first task should be rather than inventing one. |

Check the proposed replacement too. Substituting "result" for "outcome" or "mistakes" for "errors" leaves the same generic advice. Preserve the useful constraint and give a usable choice, criterion, or contextual example; delete advice that adds nothing to the surrounding instructions. General statements are fine when they explain something without making the reader supply the missing advice.

Retain clear writing even when it contains a technical term: "An idempotent request can be repeated without creating a second order." The definition makes the term useful. Retain consequential limits such as "This comparison covers one project; it does not establish which setting will work best for yours." Preserve a caveat's meaning while fixing awkward or mistaken authored wording. For example, a claim about verifying "missing evidence" should name the behavior still needing a check. Never change exact quotations or code to match the house voice.

Understanding what a sentence probably means is a lower standard than accepting it for publication. Prefer a direct action or explanation when it preserves the meaning. Do not manufacture edits to meet a quota.
