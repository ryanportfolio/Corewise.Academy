## Source checks

- **Code changes per day.** Herk's captions say "about 200 code changes a day in May". His description and Hallie (1:45) say about 2,500. Anthropic, "Redesigning source control at Anthropic", October 13, 2026, https://www.anthropic.com/research/redesigning-source-control: "In May 2026, Anthropic averaged around 2,500 code changes merged per day; as of September, we merged over 30,000 per day." The 200 is most likely a caption error. The guide uses neither figure.
- **Auto mode study.** https://claude.com/resources/articles/auto-mode-default-in-claude-code, August 7, 2026. "The testers caught the dangerous command just 13.6% of the time (143 of 1,053)" and "auto mode blocked 89% of the same commands (937 of 1,053)". "Partway through each session, a single permission prompt was swapped for a clearly dangerous command." Limits stated on the page: a test environment built for the study, participants knew they were being evaluated, and approving the prompt ran nothing dangerous. Both videos say "about 14%"; the guide gives 13.6%.
- **Auto mode default.** Permission modes page: "With Claude Code v2.1.283 or later, auto mode is the built-in starting permission mode for interactive terminal and VS Code sessions on every plan and provider." Herk says "the terminal and Claude Code desktop app". The guide follows the documentation and does not mention the desktop app.
- **What the classifier trusts.** "The classifier trusts your working directory and the remotes that were configured for it when the session started." The guide says "the online copies of the project that the folder is linked to".
- **Auto mode settings.** Configure auto mode page: entries are "prose, not regex or tool patterns"; "The classifier doesn't read `autoMode` from project settings in `.claude/settings.json` or `.claude/settings.local.json`"; `/auto-mode-setup` drafts entries "from your project and your recent sessions in it" and "You accept or discard it as a whole". The guide's JSON block is three of the five lines in the page's example, unchanged.
- **Deny rules.** "Rules are evaluated in order: deny, then ask, then allow." "Deny rules block in every mode, including `bypassPermissions`." `permissions.deny` "Blocks before the classifier is consulted." Read rules: "apply to Claude's built-in file tools, to file commands Claude Code recognizes in Bash, such as `cat`, `head`, `tail`, `sed`, and `tee`" and not to "arbitrary subprocesses that read or write files indirectly". This matches Hallie at 7:09.
- **Ask rules.** "`permissions.ask` ... The classifier cannot auto-approve a matching action." The `ask` rule block is the guide's addition; neither video mentions it. Herk's sent-email example reads more naturally as an action to approve than one to ban.
- **CLAUDE.md is context.** Memory page: "Claude treats them as context, not enforced configuration." Best practices: "`CLAUDE.md` is for guidelines, and Claude is allowed to decide a guideline doesn't apply." On emphasis: "Current ones follow a plainly worded line, and piling on emphasis mostly makes Claude over-apply the rule."
- **`/doctor prompt-audit`.** Memory page: reports "instructions written for older models, references to files or commands that don't exist, and files that contradict each other"; "nothing in your files changes until you ask Claude to apply them"; "requires Claude Code v2.1.283 or later". Both videos' captions give the command without the hyphen.
- **Sandbox.** "The sandbox runs on macOS, Linux, and WSL2. On native Windows, Claude Code runs commands unsandboxed." Off by default. Default read access: "Most of the machine, including credential files such as `~/.ssh` and `~/.aws/credentials`." Covers Bash, PowerShell, and Monitor commands; "file tools, MCP servers, and hooks run outside it". Herk's "so even a bad package can't go grab your keys" holds only with a matching deny rule, which the guide states.
- **Cloud sessions.** Available on "Pro, Max, Ultra, and Team plans, and for Enterprise users with premium seats or Chat + Claude Code seats". New environments start at Limited network access: "The default allowlist of package registries, GitHub, and cloud SDKs". Network secret: "Anthropic's agent proxy adds the key to requests for the hosts you list, after each request leaves the session's VM, so the key itself stays outside the VM."
- **Hooks.** Exit code 2: "Blocking error". Any other non-zero code: "Non-blocking error ... The action goes ahead". "If your hook is meant to enforce a policy, use `exit 2`." Per event: `PostToolUse` "Shows stderr to Claude; the tool already ran"; `Stop` "Prevents Claude from stopping"; `TaskCompleted` "Prevents the task from being marked as completed". Best practices: "If the hook blocks eight stops in a row with no tool call between them, Claude Code overrides the next block and ends the turn." The `Stop` hook block is the best practices page's example, unchanged.
- **`/goal`.** Best practices: "sets a condition that a separate model checks against the conversation after every turn, and Claude keeps going until it's met". The guide's example condition is shortened from the page's.
- **Code Review.** "Several agents read each change"; "A verification step checks findings against the code"; Team and Enterprise plans; `/code-review` "on any plan". Hallie does not name the product at 14:38. The guide says Anthropic offers "a review of this kind", which is the guide's reading.
- **Projects.** "Projects are in public beta on Pro, Max, and Ultra plans and rolling out gradually ... Projects aren't offered on Team or Enterprise plans yet." "A new project runs Opus everywhere, with high effort for threads and low effort for the conversation." "A new project runs every thread on Opus at high effort, which draws on your plan fastest." "Threads compact automatically." Hallie says "a model like Fable" and "like Opus 5.5"; the guide says she suggests them.
- Not verified: Hallie's statement that auto mode became the default "back in August" for every reader's plan (the article lists Pro, Max, Ultra, and Team on that date); CI auto-fix and merge when ready, which the guide omits.
- Nothing in this guide was run. No auto mode entry, deny rule, sandbox, hook, cloud session, or project was configured or tested for this ingest.

## Checks added during revision

- **Starting a cloud session.** Use Claude Code in the cloud page: surfaces are the browser at claude.ai/code, the Code tab in the Claude app, the desktop app, and `claude --cloud`. "Platform restrictions: repository cloning in Anthropic-hosted environments and pull request creation require GitHub." The page also describes `claude --cloud` uploading a local git repository that has no remote; the guide gives the GitHub path only.
- **Seeing the mode.** Permission modes page: "press `Shift+Tab` to cycle permission modes" and the status bar shows `⏵⏵ auto mode on`.
- **Auto mode on every plan.** The reviewer flagged the body's "on every plan" against the August article's title, which lists Pro, Max, Ultra, and Team. The permission modes page settles it: "With Claude Code v2.1.283 or later, auto mode is the built-in starting permission mode for interactive terminal and VS Code sessions on every plan and provider. On earlier versions, it's the built-in starting permission mode only on Pro, Max, Ultra, and Team plans."
- **Ask rule.** The `"ask": ["Bash(git push *)"]` line is from the Configure auto mode page's recipe. That page notes a push written another way, such as `git -C <dir> push`, does not match; the guide does not carry that caveat.
- **Sandbox or cloud session.** "The sandbox is for work that stays on your own computer. Hallie prefers a cloud session for runs that last hours" is the guide's reading of 8:16 ("if you're running it locally") and 9:23 to 9:40 ("ideally you want this whole thing to run somewhere where none of that is even there", "definitely something you want for these longer running sessions").
- **The signed-in check.** "If one check is that existing users stay signed in" is the guide's own illustration. Hallie says only that the run "doesn't get past that first check" (12:03).
